# `resume-parsing-service` — Data Dictionary

**Service:** `resume-parsing-service`
**Prepared:** 22 July 2026
**Status:** starting point — expected to expand as the service evolves.
**Sources:** `resume-parsing-service` Doc 00 · Epic Docs 01 → 08 (for consumer expectations only).

---

## 1. Scope

**This service is stateless and has no database.** It receives a document, returns typed JSON, and retains nothing. There are therefore no tables, no persisted entities, no relationships and no migrations to document — **this dictionary is a wire contract.**

Everything durable lives in `user-service`, which already has its own schema. **This document does not describe, duplicate or propose changes to it.** Where a `user-service` field is named below, it is only to explain why this service behaves a particular way — never as a definition.

### 1.1 Conventions

| Marker | Meaning |
|---|---|
| **R** | Required — always present |
| **O** | Optional — may be absent, null or empty. Absence is normal and never an error |
| **S** | System-generated by this service |

### 1.2 Rules governing every field

Not repeated per row.

1. **Extracted values are untrusted input.** They originate in an arbitrary document interpreted by a model. Consumers escape them at every render point.
2. **Empty-equivalent normalises to absent.** Empty string, whitespace-only, and the literal strings `"undefined"` and `"null"` are returned as `null`, never passed through.
3. **Never invent, infer or repair a value.** No default dates, no reconstructed ranges, no corrected ordering. Implausible values are returned as written and the consumer decides.
4. **Fill any existing consumer field a resume can supply; never originate one.** The fields below are **illustrative, not a whitelist**. A field appears here because `user-service` already has it — never the reverse.

## 5. Value handling

Applies to every string field returned.

| Concern | Rule |
|---|---|
| Character encoding | UTF-8. Unicode **normalised**, never ASCII-stripped — non-Latin scripts must survive intact |
| Whitespace | Trimmed. Internal runs collapsed |
| Case | **Preserved as written.** Normalisation for matching is the caller's job |
| Length | No truncation in the response. Display truncation is the caller's concern |
| Markup and control characters | Returned as inert text. This service never interprets document content as instruction |
| Malformed model output | Never passed through. A response that cannot be validated against this contract is a `parse_failed`, not a partial result |

### 5.1 Prompt injection

Resume content is **untrusted input**. A document containing text addressed to the model — instructions, role claims, attempts to alter the output shape — is a document, not an instruction. The response contract is enforced after generation, so an injected instruction cannot change the shape of what this service returns.

## 8. Resolved gaps

All three gaps previously listed here are closed. Rulings and their research basis are in `resume-parsing-service-GAP-RESOLUTIONS.md`.

| # | Was | Ruling |
|---|---|---|
| 1 | Multilingual behaviour untested | **Mixed-language is the normal case.** Never declare or select a language. Extract as written, never translate. `meta.detectedLanguages` added for per-language measurement. No support claimed until measured per-language |
| 2 | Truncation point undefined | **Ceiling 150,000 characters**, far above any legitimate resume. Never chunk. Above the ceiling, truncate at a paragraph boundary keeping the head and set `meta.truncated`. Above 500,000 characters, reject as `422 UNREADABLE_DOCUMENT` without a model call |
| 3 | No evaluation corpus | **50 documents, stratified to our own talent population.** Tier A synthetic and committed, Tier B real and never committed. Per-field F1 thresholds. No prompt or model change ships without a Tier A run |

### 8.1 New `meta` fields

These are observability only. **The `result` schema is unchanged** — no new profile-bound field is introduced.

| Field | Type | Purpose |
|---|---|---|
| `detectedLanguages` | array\<string\> | Languages observed in the document. Enables per-language quality measurement, which aggregate metrics cannot show |
| `truncated` | boolean | True where extracted text exceeded the ceiling. **The caller may tell the talent; it must never be silent** |
| `extractedCharacters` | number | Character count after text extraction |

## 9. Expansion rules

1. **A field appears here because `user-service` already has one.** Extraction never originates a field, and this document never proposes a schema change to the consumer.
2. **If a row ever needs a "persisted" column, something has gone wrong.** This service holds no state. Needing to store something is a signal that responsibility belonging to `user-service` has migrated here — an architectural warning, not a dictionary update.
